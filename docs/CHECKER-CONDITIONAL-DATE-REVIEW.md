# Conditional dose dates — `conditionalProjectedFromDate` audit

Generated by `scripts/conditional-date-audit.ts`. **No medical rules were changed.**

## Policy (your decision)

- Use **`conditionalProjectedFromDate` only** when the next dose date is anchored to a **known or planned user-entered primary date** (e.g. Varicella dose 1 scheduled after MMR).
- When projection assumes **“if dose 1 is given today”** (`referenceDate`), show **`recommendedDate` only** — do **not** invent `conditionalProjectedFromDate`.
- When timing depends on **future unknown product/condition** (e.g. PCV zero-history product choice), **do not** show a conditional row (engine skips via `shouldShowPcvZeroHistoryProductSchedules`).

## Where the field is set in code

| Location | Behavior |
|----------|----------|
| `conditional-upcoming.ts` → `buildConditionalUpcomingRecommendations` | Sets `conditionalProjectedFromDate` **only** for Varicella when `projectedDose1Date` is **not** the same calendar day as as-of (uses planned upcoming D1 date). |
| `result-presentation.ts` | Uses field **only** for translation key `resultConditionalVaricellaDose2FromPlannedDose1`. |
| MenB / MenACWY / PCV infant booster append helpers | Separate conditional rows with windows or minimum dates; **no** `conditionalProjectedFromDate`. |

## Audit findings

### 1. Date shown despite insufficient information?

- **PCV / MenACWY with unknown product:** conditional next-dose rows are **suppressed** when product is unknown (`getConditionalNextDoseDateForItem` returns null for MenACWY unknown; PCV uses `shouldShowPcvZeroHistoryProductSchedules`). **No inappropriate fixed date** in those cases in sampled runs.
- **MenB / MenACWY booster “minimum start” rows:** show a **minimum date** computed assuming dose 1 at **as-of** — parent copy should treat as **hypothetical**, not documented history. This is intentional “if given today” semantics.
- **HPV with `dontKnow` product:** conditional dose 2 appears only when `canProjectHpvTwoDoseWithoutProduct` passes; otherwise no row — verify clinically if age-only projection is desired (not changed here).

### 2. Calculable anchor date missing `conditionalProjectedFromDate`?

- **127** sampled rows have **no** `conditionalProjectedFromDate` — expected for as-of-based projections (Rota, PCV, MenB, MenACWY dose 2, Influenza, HepA, HPV, etc.).
- **2** rows **do** set it — all sampled cases are **Varicella dose 2** where dose 1 is a **future planned date** (MMR interval), not “today”.

### 3. Wrong dose / wrong anchor date?

- **Varicella after recent MMR:** conditional D2 date = **planned D1 + interval**; `conditionalProjectedFromDate` = **13/09/2026** (MMR+28d), matching `medical-engine.test.ts`.
- **Varicella when MMR same day as as-of:** D1 due now; conditional D2 uses **today** as projected D1 → **no** `conditionalProjectedFromDate` (same-day rule in `buildConditionalUpcomingRecommendations`). Presentation falls back to generic conditional copy with `recommendedDate` only.
- **No evidence** in canonical scenarios that `conditionalProjectedFromDate` points at the wrong dose; field is **not** used for non-Varicella categories in current code.

## Open question (not a code change)

Should Varicella **same-day MMR + D1 due now** use explicit copy that D2 is from **today**, without adding `conditionalProjectedFromDate`? Current UI uses `resultConditionalNextFixedDose` with as-of-based math.
